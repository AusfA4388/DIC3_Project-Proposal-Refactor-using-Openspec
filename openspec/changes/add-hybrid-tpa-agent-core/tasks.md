# Tasks

> 開始實作前，請先在 design.md 的「待小組決議事項」Q1–Q7 取得共識，並更新對應的 spec。

## 1. 專案設定

- [ ] 1.1 建立 Python 專案結構（`src/`、`tests/`、`data/`），並確認 `pytest` 可以執行
- [ ] 1.2 決定市場、標的、時間框架與回測期間，記錄於 DESIGN.md，並確認測試期間晚於所用 LLM 的知識截止日

## 2. 使用者設定與資料層（user-preference、market-data-ingestion）

- [ ] 2.1 實作使用者設定（標的、時間框架、風險比例、帳戶權益）與驗證；驗證：不支援的時間框架與缺少風險設定的測試通過
- [ ] 2.2 實作 OHLCV 資料取得與時間排序；驗證：時間戳嚴格遞增的測試通過
- [ ] 2.3 實作資料品質檢查（缺漏、重複、最高價低於最低價）；驗證：三種異常各有測試案例且通過
- [ ] 2.4 實作延遲凍結（> 2 秒）與中斷警報（> 30 秒）；驗證：以模擬延遲與中斷的測試通過

## 3. 供需區引擎（supply-demand-zone-detection）

- [ ] 3.1 實作 Swing High／Low 偵測；驗證：以人工構造的 K 棒序列測試偵測結果
- [ ] 3.2 實作供需區輸出（上緣、下緣、類型、形成時間、測試次數）與成交量確認；驗證：低成交量候選區被排除的測試通過
- [ ] 3.3 實作 S/R Flip 角色轉換；驗證：收盤跌破需求區後轉為壓力區的測試通過
- [ ] 3.4 驗證可重現性：同一資料重跑兩次，輸出完全相同的測試通過；並在文件中附一張供需區標記圖

## 4. 勝率模型（win-rate-prediction）

- [ ] 4.1 實作特徵萃取（區域距離、區域寬度、ATR、成交量 Z-score、動量指標）；驗證：特徵只使用決策時間點以前資料的測試通過
- [ ] 4.2 實作 barrier 標籤（N 根 K 棒內先觸及停利為勝）；驗證：先觸及停利、先觸及停損、都未觸及三種案例的測試通過
- [ ] 4.3 依時間切分資料並訓練 XGBoost；驗證：測試集最早時間晚於訓練集最晚時間
- [ ] 4.4 產出評估報告（準確率、Brier score、校準圖、特徵重要度），記錄於 `docs/results/`

## 5. 知識庫與推理代理人（price-action-knowledge-base、planner-reasoning-agent）

- [ ] 5.1 建立價格行為規則庫（S/R Flip、假突破、回測確認、風險優先、RR 公式），每條規則有識別碼；驗證：依識別碼與情境查詢的測試通過
- [ ] 5.2 定義推理代理人的結構化輸入與輸出格式（JSON schema）；驗證：格式驗證測試通過
- [ ] 5.3 實作 LLM 推理呼叫與一致性檢查（輸出數值須與輸入一致）；驗證：以不一致輸出模擬的測試會被標記為無效
- [ ] 5.4 實作 LLM 失敗、逾時、無法解析時的 WAIT／NO_TRADE 處理；驗證：逾時模擬測試通過

## 6. 決策與風控（trade-decision-risk）

- [ ] 6.1 實作停損（區域外側 + ATR 緩衝）與停利（下一個反向區域）；驗證：缺少目標區時回傳 WAIT／NO_TRADE 的測試通過
- [ ] 6.2 實作 RR、E 與雙門檻判斷；驗證：W=0.55、RR=2.0 時 E=0.65，以及兩個門檻案例的測試通過
- [ ] 6.3 實作倉位計算；驗證：可承受虧損 1,000、進場 100、停損 98 時倉位為 500 的測試通過

## 7. 報告輸出（trade-report-output）

- [ ] 7.1 實作結構化報告（APPROVED 與 WAIT／NO_TRADE 兩種格式），含證據鏈與降級警告；驗證：欄位完整性測試通過
- [ ] 7.2 確認系統不會自動送出任何委託；驗證：程式碼中無下單呼叫，且有對應測試

## 8. 整合與評估

- [ ] 8.1 串接完整流程，對一個標的產出端到端報告；驗證：README 中的執行指令可以重現該報告
- [ ] 8.2 回測並與均線交叉、RSI 策略比較勝率、RR、MDD（含手續費與滑價）；驗證：結果表格記錄於 `docs/results/`
- [ ] 8.3 消融實驗：分別移除 LLM、ML、供需區，比較績效差異；驗證：結果表格記錄於 `docs/results/`
- [ ] 8.4 門檻敏感度分析（Trade-off T1）：不同 W、RR 門檻下的訊號數量與期望值；驗證：曲線圖記錄於 `docs/results/`
